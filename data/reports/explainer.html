Key findings

  • Volume: 61,907 labelled examples across two years and two splits — comfortably past the 'tens of thousands of instances' threshold the A2 spec asks for.
  • Class balance: 2015 training 4,010–4,500 per class; 2017 training 4,492–4,948. Both stratified — FA slightly under-represented.
  • Length explosion: median Stub ~1,381 chars; median FA ~41,692 chars (~30× larger). Length alone is a very strong baseline signal.
  • Citation depth: median <ref> tags climb 0 (Stub) → 14 (C) → 48 (GA) → 90 (FA).
  • Schema drift: 2015 has pageid, revid, ordered_class; 2017 adds talk_pageid, talk_revid and renames the label to rating. A unified loader normalises both.
  • Temporal overlap: 5,862 pageids in both years; 5,755 (98.2%) keep the same label. Natural temporal-generalisation RQ.
  • Storage shape: Label TSVs are tiny; the bulk (1.4 GB) is wikitext — 63k blobs, one per revid. Always index by revid; never walk the directory.

A2 requirementHow this dataset satisfies it
Tens of thousands of instances61,911 labelled rows — well past the bar.
Complex feature space / engineering opportunity Each row points to a full raw-wikitext document. The feature space is whatever you engineer.
≥1 pre-processing / feature construction step Mandatory: wikitext → structured features (see §6).
≥2 research questions (3-person)Five candidates in §11.
≥3 ML models + ≥1 NNSuggested line-up in §12.
Hyper-parameter tuned per model Every suggested model has obvious knobs (C, depth, n_estimators, hidden_layer_sizes, …).
3+ evaluation metrics For a 6-class ordinal problem: accuracy, macro-F1, confusion matrix, per-class P/R, MAE on level.
Validation strategyProvided test set + stratified 5-fold CV on training (see §13).
Publicly available, cite original Warncke-Wang et al. (CHI 2015) and 2017 update.
Bottom line: well-sized, structured, ordinal (rare and interesting), supports both 'structural-only' and 'text-content' research questions.

Why one file per revid? The dataset is content-addressable: knowing a revid is enough to fetch its snapshot. Cheap to ship but slow to walk — never iterate the directory in your pipeline; index by revid instead.

5. Wikipedia quality classes

Wikipedia editors grade articles on an ordinal scale. The classes are defined by community policy on WikiProject pages.

ClassFull nameMeaningTypical size
StubStubA few sentences. Barely useful as an article.100–500 chars
StartStart-classSome content but obviously incomplete or unbalanced.1–3 KB
CC-classSubstantial but missing important material.3–10 KB
BB-classMostly complete, well-referenced, minor issues.10–30 KB
GAGood ArticlePassed a formal GA review — solid quality.20–60 KB
FAFeatured ArticlePassed FA review — Wikipedia's highest grade.40–120 KB
Treat the label as ordinal, not nominal. A model that predicts "FA" for a Stub is much worse than one predicting "Start" — your metrics should reflect that.

7. Feature dictionary

Length features

chars

What: Total character count of raw wikitext.

Signal: Strongest single signal. Higher quality = much longer articles.

Expected per class: Increases monotonically with class. FA medians can be 100×+ Stub.

tokens

What: Whitespace-tokenised words.

Signal: Same as chars but ratio with chars hints at language vs markup density.

Expected per class: Monotonic increase.

lines

What: Newline count.

Signal: Caps structural size.

Expected per class: Monotonic but dominated by sections + lists in higher classes.

paragraphs

What: Blocks separated by blank lines.

Signal: Proxy for prose density.

Expected per class: Rises with class then plateaus around B/GA/FA.

sentences

What: Approximate sentence count via [.!?] splits.

Signal: Rough but useful — pairs with avg_sent_len.

Expected per class: Rises with class.

Lexical features

avg_word_len

What: Mean characters per token.

Signal: Slight signal — formal articles use longer Latin-derived words.

Expected per class: Weak positive correlation.

avg_sent_len

What: tokens / sentences.

Signal: Stylistic — well-edited prose has consistent sentence length.

Expected per class: Mostly noise alone; useful with other features.

type_token_ratio

What: Unique tokens / total tokens.

Signal: Higher = more vocabulary diversity.

Expected per class: DROPS with class because long articles repeat function words; this inversion is informative.

Markup features

wikilinks

What: [[…]] openings (internal Wikipedia links).

Signal: Strong signal — better articles link more concepts.

Expected per class: Increases sharply; FA articles often have 100s.

extlinks

What: Bare [https://…] external links.

Signal: Indicator of source attribution outside ref tags.

Expected per class: Increases with class.

templates

What: {{…}} openings (transclusions).

Signal: Infoboxes, navboxes, citation templates etc.

Expected per class: Increases steeply with class; FA articles use dozens.

images

What: Image and file embeds.

Signal: Visual richness.

Expected per class: Stub/Start have ~0; B/GA/FA have several.

refs

What: tags (citations).

Signal: GA/FA require strong sourcing; very discriminative for top classes.

Expected per class: Near 0 for Stub; tens to hundreds for FA.

Structure features

headings

What: Lines starting with `==`.

Signal: Section count.

Expected per class: Stubs have 0–1; FA has 6–15.

max_heading_depth

What: Deepest heading level (=, ==, ===, …).

Signal: Captures hierarchical structure.

Expected per class: Stubs flat (2); FA can reach 4–5.

tables

What: `{|` opens (wikitable starts).

Signal: Statistics, results, etc.

Expected per class: Most evident in GA/FA on scientific or sports topics.

list_items

What: Lines starting with `*` or `#`.

Signal: Bulleted/numbered list density.

Expected per class: Rises modestly; lower classes use ad-hoc bullets, higher classes use prose.

has_infobox

What: Whether `{{Infobox` appears.

Signal: Binary — does the article have an infobox at all?

Expected per class: Stub:~10%, FA:~95%.

Style features

bold

What: Pairs of `'''` (bold markers).

Signal: Disambiguation bolds + key terms.

Expected per class: Weak positive correlation.

italic

What: Pairs of `''` (italic markers).

Signal: Titles of works etc.

Expected per class: Weak positive correlation.

Meta features

categories

What: [[Category:…]] links at the bottom.

Signal: Categorisation effort.

Expected per class: Increases with class.

Layer-2 features (easy adds): TF-IDF unigrams/bigrams over the lead section; readability scores (Flesch–Kincaid); outgoing-link entropy; edit-history metadata (number of contributors); pre-trained sentence embeddings.

11. Suggested research questions

RQ 1

Can we predict an article's quality class from purely structural features (no text content)?

Uses only counts of templates, refs, images, headings, etc. — interpretable and fast. Directly answers whether 'editing effort signals' alone capture quality.

RQ 2

How much additional accuracy comes from text content (TF-IDF, embeddings) over structural features?

Sets up a clean ablation: structural baseline → +unigram TF-IDF → +BERT embeddings.

RQ 3

How stable is article quality across two years? Can a model trained on 2015 predict 2017 labels for the same pageids?

Tests temporal generalisation — train on 2015, evaluate on 2017 shared pageids with the 2017 label as ground truth.

RQ 4

Is the ordinal structure (Stub < Start < C < B < GA < FA) better captured by ordinal regression than by flat classification?

Compares macro-F1 of multiclass softmax vs ordinal logistic regression / regression-then-bin.

RQ 5

Which classes are systematically confused, and does the confusion match human-rater disagreement reported in the Wikipedia QA literature?

Driven by the confusion matrix; ties into Discussion.

13. Validation strategy

  1. Provided test sets are untouched final evaluators. No peeking during model selection.
  2. Stratified 5-fold CV on training for hyper-parameter tuning. RandomizedSearchCV is enough.
  3. Report CV mean ± std (training) and test numbers (one shot).
  4. Cross-year transfer (optional RQ): train on 2015, evaluate on 2017's labels for shared pageids.
  5. Metrics: accuracy, macro-F1, weighted-F1, MAE on level, 6×6 confusion matrix.

14. Risks & gotchas

  • Length is too good a feature. A model using only chars gets respectable accuracy — fine as baseline, not enough for a 25-mark report.
  • Stub vs Start blurs. Both are 'incomplete' — expect most off-diagonal confusion there.
  • 2015 and 2017 share six classes but Wikipedia's editorial bar shifted. Don't naïvely concatenate them unless justified.
  • The wikitext is messy. Regex counts are robust; full text features (TF-IDF, BERT) need cleanup.
  • Talk-page features (2017 only) are tempting but uneven. If used, report results with and without.
  • A2 forbids AI-generated paragraphs in the report. Allowed: ideation and short paraphrasing only. Declare in the AI usage section.
